# Требования и пользовательские истории

## Роли

| Роль | Задача |
| --- | --- |
| Студент | Смотреть пары своей группы, видеть задания, записываться в очередь и отслеживать позицию. |
| Преподаватель | Создавать предметы и пары, открывать и закрывать запись, отмечать результаты сдачи. |
| Администратор | Настраивать группы, студентов, рейтинг и расписание. |

## User stories

| Заголовок | Как | Я хочу | Чтобы |
| --- | --- | --- | --- |
| Просмотр расписания | студент | открыть календарь занятий своей группы | быстро понять, какие пары и сдачи есть сегодня |
| Запись в очередь | студент | записаться на сдачу практики в открытой очереди | попасть в список сдающих без ручной переклички |
| Позиция в очереди | студент | увидеть свою позицию после формирования очереди | понимать, когда подойти к преподавателю |
| Создание пары | преподаватель | добавить предмет, аудиторию, время и длительность занятия | подготовить расписание для студентов |
| Управление очередью | преподаватель | открыть запись, закрыть её и сформировать порядок | быстро получить справедливый список сдающих |
| Отметка сдачи | преподаватель | отметить “вовремя”, “поздно” или “не сдал” | обновить рейтинг и историю студента |
| Перенос несдавших | преподаватель | перенести несдавших на следующую пару | не потерять долги между занятиями |

## Функциональные требования

1. Приложение должно работать как Telegram-бот и Telegram WebApp.
2. Студент регистрируется через `/start`, указывая ФИО и учебную группу.
3. WebApp показывает расписание с фильтрацией по группе студента.
4. Пара хранит дату, время начала, длительность, аудиторию, преподавателя и предмет.
5. Студент может записаться только в открытую очередь и только на пару своей группы.
6. Сервер проверяет Telegram WebApp `initData`; клиентский `user_id` не считается доверенным.
7. Преподаватель может управлять предметами, парами и очередями из Telegram-кнопок и WebApp.
8. После закрытия очереди участники сортируются по рейтинговой категории, а внутри категории перемешиваются случайно.
9. Результат сдачи меняет рейтинг: вовремя `+10`, поздно `+2`, не сдал `-10`.
10. Несдавшие могут быть перенесены в очередь следующей пары.

## Макеты экранов

| Экран | Содержание |
| --- | --- |
| Мои занятия | Верхняя навигация “Пульс РТУ МИРЭА”, календарь месяца, список пар выбранного дня, карточки с временем, типом, аудиторией и преподавателем. |
| Карточка пары | Детали занятия, задания, статус очереди, список участников, кнопка записи или выхода. |
| Сервисы | Для администратора: создание предметов, создание пар, список предметов. Для студента: краткая сводка по очередям. |
| Настройки | Профиль Telegram/WebApp, ФИО, группа, рейтинг и статистика сдач. |

## Нефункциональные требования

1. Данные хранятся в SQLite и сохраняются между перезапусками контейнера через volume.
2. Конфигурация передаётся через переменные окружения.
3. Приложение должно запускаться локально, в Docker и на PaaS-платформах.
4. WebApp должен быть адаптивным: desktop/tablet layout похож на журнал “Пульс РТУ МИРЭА”, мобильный layout остаётся удобным внутри Telegram.
