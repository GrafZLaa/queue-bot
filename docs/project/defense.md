# План защиты проекта

## Структура презентации

1. **Название и команда**  
   Queue Bot: Telegram-бот и WebApp для управления очередями сдачи практик.

2. **Проблема**  
   На практиках очередь часто ведётся вручную: студенты спорят о порядке, преподаватель тратит время на перекличку, несдавшие теряются между занятиями.

3. **Цель приложения**  
   Свести расписание, задания, запись и порядок сдачи в один Telegram-интерфейс, которым студент пользуется без отдельной регистрации на сайте.

4. **Роли пользователей**  
   Студент смотрит расписание и записывается. Преподаватель создаёт пары и управляет очередью. Администратор поддерживает данные студентов.

5. **Архитектура и стек**  
   Python, aiogram, aiohttp, SQLite, Telegram WebApp SDK, Docker, MkDocs.

6. **Основной функционал**  
   Регистрация, расписание по группе, задания, запись/выход из очереди, формирование порядка, рейтинг, перенос несдавших.

7. **Фишка проекта**  
   Очередь формируется не только по факту записи, а с учётом рейтинговой категории и случайного порядка внутри категории.

8. **Аналоги**  
   Таблицы Google, чаты Telegram, LMS/СДО. Отличие Queue Bot: всё происходит прямо в Telegram и связано с расписанием пары.

9. **Демонстрация**  
   `/start`, открытие WebApp, выбор даты, запись в очередь, закрытие очереди админом, отметка сдачи.

10. **Итоги и развитие**  
    Добавлена Docker-доставка, документация, защита WebApp initData, тесты. Возможное развитие: импорт расписания из внешней системы и настоящая QR-отметка присутствия.

## Короткий сценарий демонстрации

1. Запустить приложение и открыть бота.
2. Показать регистрацию студента с группой.
3. Открыть “Мои занятия” и выбрать дату.
4. Открыть карточку пары и нажать “Записаться”.
5. Перейти в админский режим, закрыть очередь.
6. Показать сформированную позицию и отметку сдачи.
