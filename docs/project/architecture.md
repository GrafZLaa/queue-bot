# Архитектура

## Стек

| Слой | Технологии |
| --- | --- |
| Telegram-бот | Python, aiogram 3 |
| WebApp и HTTP API | aiohttp, HTML, CSS, JavaScript, Telegram WebApp SDK |
| Хранение данных | SQLite, aiosqlite |
| Документация | MkDocs, mkdocstrings |
| Доставка | Docker, Railway/Procfile |

## Компоненты

```text
Telegram Client
    │
    ├── Bot API: команды /start, рейтинг, админские действия
    │
    └── Telegram WebApp: журнал, запись, админский режим
            │
            ▼
aiohttp API внутри queue_bot.main
            │
            ├── проверка Telegram initData
            ├── фильтрация расписания по группе
            ├── операции очереди
            └── админские операции
            │
            ▼
queue_bot.database
            │
            ▼
SQLite: users, subjects, classes, assignments, queues, entries
```

## Основной сценарий студента

1. Студент пишет боту `/start`.
2. Бот сохраняет ФИО и группу.
3. Студент открывает WebApp из кнопки “Открыть журнал занятий”.
4. WebApp отправляет `X-Telegram-Init-Data` на сервер.
5. Сервер проверяет подпись Telegram и определяет пользователя.
6. Расписание фильтруется по группе студента.
7. При открытой записи студент вступает в очередь.

## Основной сценарий преподавателя

1. Telegram ID преподавателя указан в `ADMIN_IDS`.
2. Преподаватель открывает админ-панель в боте или вкладку “Сервисы” в WebApp.
3. Создаёт предметы и пары с длительностью занятия.
4. Открывает запись для студентов.
5. Закрывает запись; сервер формирует порядок очереди.
6. После сдачи отмечает результат и обновляет рейтинг.

## Алгоритм очереди

Очередь строится по рейтинговым категориям:

| Категория | Условие | Приоритет |
| --- | --- | --- |
| Добросовестный | рейтинг `>= 65` | первая группа |
| Средний | рейтинг `36..64` | вторая группа |
| Отстающий | рейтинг `<= 35` | третья группа |

Внутри каждой категории порядок случайный. Такой подход сохраняет мотивацию сдавать вовремя, но не делает порядок полностью ручным или предсказуемым.
